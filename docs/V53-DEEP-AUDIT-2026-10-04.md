## CSS debt

The active public CSS is correctly routed through src/styles/public-system.css, but the repository still contains many superseded V13–V42 stylesheet generations and historical QA scripts.

After one final visual regression checkpoint, keep the active CSS layers, archive/remove superseded layers, and reduce the default QA suite to one canonical release suite.

## Photo system

V20.3 Photo System introduced WebP assets, lazy loading, async decoding, stable crops, real image layers, alt/event/club/album associations, optimized uploads and object-URL cleanup.

Current V52 extends this with source-media taxonomy, event mapping, provenance, photo-integrity QA and local runtime asset QA.

Remaining live-data work: verify every production gallery row for URL, storage path, caption, alt, type, provenance, club, event, album, publication state, archive state, duplicate URL and claimed identity.

## Club truth audit

The current code contains 21 maintained communities from supplied JYC material. Newer official JIIT 2026 material confirms a different and more nuanced structure across Sector 62 and Sector 128, while current public club sources also demonstrate active communities that are not all represented by one brochure.

Do not blindly replace the current 21. Introduce a verification model with community, campus, source, evidence date, official link and publication state.

Recommended states: verified-current, verified-current-unlisted-in-brochure, historical, needs-verification, archived.

## Social and event truth

Verify every populated club social link against the actual public profile, add a source and verification date, and leave uncertain handles blank.

For every published event verify date, time, venue, registration destination, official URL, organiser, status, archive state, poster, gallery, contact information, eligibility, prizes and timeline.

Time-sensitive registration links should automatically become visually stale/closed when their deadline passes.

## JYC Now

The current API aggregation layer supports Instagram, YouTube, LinkedIn, RSS and manual sources. Before production use, verify provider credentials, API versions, rate limits, failure isolation, caching, sync-secret protection and stale-item expiry.

## Security

The repository has strong security intent: publishable browser key only, protected Edge Functions, media write boundary, public-submission boundary, error-report boundary, private backups, RLS/role-aware writes, CSP, CodeQL and npm audit.

Next security step is operational proof that those controls are deployed and behaving correctly in the live Supabase project.

## Accessibility and performance

Existing QA covers focus and reduced motion. Manual production checks still need keyboard navigation, dialog focus traps, Escape handling, focus restoration, heading hierarchy, form errors, alt quality, contrast, 200 percent zoom and 320px width.

Performance QA has budgets for JS, CSS, image and source-map output. Real Lighthouse measurements are still required after final media ingestion, including mobile, slow 4G, image-heavy gallery, club detail and event detail.
